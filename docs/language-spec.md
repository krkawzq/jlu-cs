版本：Prim Core 1，2026-10-19。状态：**Core 1 语义规范，Rust 解释器与手动 JIT 已实现**。当前工程边界见 [实现说明](../src/prim-rs/README.md)。

本文定义语言的语义；[词法规则](lexical-spec.md)定义源码如何切分，[Lexer](lexer-design.md)定义扫描器接口，[Parser](parser-design.md)定义完整文法、AST 和名字解析，[JIT](jit-runtime.md)定义手动编译协议。发生冲突时，语义以本文为准，文法以 Parser 为准，Token 以词法规则为准；实现前必须消除冲突，不能自行择一解释。[项目计划书](项目计划书.md)据此组织实施与验收。历史 PDF、PPT 属于历史材料；根目录 `examples/` 和 `src/prim-rs/examples/` 提供当前实现的可运行示例。

## 1. 课设目标与设计约束

Prim 要展示的是：用很少的语义机制，把函数、对象、状态和本机执行组合起来。成功标准是可以精确解释每一步，而非语法数量或跑分。

核心命题是：

> **一切皆闭包：closure 是静态的数据，closuring 是动态构造数据的过程。对象是立即执行的 closuring，函数是延迟执行的 closuring。**

五条必须保持的原则：

1. **绑定、槽和值分离。** 名字指向槽，槽保存值；修改槽和修改值所指的对象是两件事。
2. **捕获显式。** 延迟执行的 closuring 必须列出外部依赖，禁止自动捕获整个父作用域。
3. **复制规则唯一。** 值复制从不隐式深拷贝；共享变量槽只通过显式 `&` 建立。
4. **对象与函数同源。** 二者都是 closuring，只是执行时机不同；使用同一种槽、环境布局、字段访问和内存管理。
5. **执行方式不改变语义。** `@jit` 手动选择本机执行；参数、捕获、错误和副作用与解释执行一致。

不把所有语句强行做成表达式。`let`、赋值和控制转移是语句；块、条件、循环和闭包构造是表达式。这个区分让返回值与控制流可以直接阅读。

### 1.1 closure 与 closuring

closuring 指“在新作用域中执行一段语句，由其中的 `let` 逐个建立槽”的过程；closure 是这一过程留下的环境，即一组名字到槽的有序绑定，是静态的数据。Prim 只有这一种构造数据的机制，区别仅在于 closuring 何时执行：

| 写法 | closuring 何时执行 | 求值结果 |
| --- | --- | --- |
| `@{ let a = ...; }` | 立即 | 本次 closuring 留下的环境，即 closure；`a` 成为字段 |
| `$[caps](params) { body }` | 延迟到每次调用 | 函数：已经固定的捕获环境，加上尚未执行的 closuring |

因此函数与对象不是两类事物：对象是已经完成的 closuring，函数是被推迟、可以反复执行的 closuring。实现上二者共用同一套作用域与语句降低：`@{}` 把执行后的作用域直接发布为字段（`MakeData`），函数体在每次调用时以同样方式建立参数槽与局部槽。

由此直接得到以下规则：

1. **只有延迟的 closuring 需要捕获列表。** 函数体在之后某次调用时才执行，那时定义处的作用域可能已经改变或已经离开，所以必须在构造时声明从当下带走什么：`[x]` 把当前值固定为闭包私有槽，`[&x]` 与外层持续共享同一槽。`@{}` 立即执行，外层作用域仍然存在，直接读取即可。
2. **函数值本身也是 closure。** 函数值中已经固定的部分是捕获环境，它是静态数据，所以捕获项就是函数的字段，可以通过 `f.n` 读写；参数与局部变量要到调用时的 closuring 才出现，因此不是字段。
3. **`@{}` 没有尾表达式。** 立即 closuring 的产物就是环境本身，没有另外的返回位置。函数调用返回函数体尾值；调用环境默认不发布，只有被内层闭包捕获的槽继续存活。
4. **构造器是两种 closuring 的嵌套。** `$[](x, y) { @{ let x = x; let y = y; } }` 每次调用时执行一次立即 closuring 并交出结果；对象中的方法是在立即 closuring 过程中创建的延迟 closuring，通过 `[&value]` 连回同一槽。
5. **`self` 指当前正在执行的 closuring 所属的函数值。** 递归就是再执行一次同一个 closuring。

“一切”指用户能构造的一切数据与抽象：对象、函数、数组（`std.array`）、多返回值以及标准环境 `std` 本身都是 closure。`int`、`float`、`bool`、`str`、`unit` 是计算的叶子，是写入槽中的值而不是被构造出的环境，不要求实现为带字段表的对象。

## 2. 最小语言范围

Core 1 必须完成：

- `int`、`float`、`bool`、`str`、`unit` 与闭包值。
- 词法作用域、变量槽、显式别名、值捕获与槽捕获。
- 闭包构造、调用、高阶函数、递归、字段读写。
- `if`、`loop`、`break`、`continue`、`return`。
- 通用装饰器与手动 `@jit`，动态链接 LLVM、ORC 进程内编译与执行。
- 定位到源码的诊断，以及能回收循环结构的内存管理。
- 行输入/整段 stdin、stdout/stderr、终端按键与绘图、计时与 UTC 日历、随机数、数组与序列、位运算、文件与目录、进程与系统信息、AST 解析、运行时检查与内存诊断内置接口；可运行终端贪吃蛇。

Core 1 不包含：类与继承、运算符重载、类型注解、自动类型转换、解构、默认/命名/变长参数、列表/字典/元组字面量、索引/切片语法、循环标签、`for`/`while`、模块导入、异常捕获、并发、宏、自动热点 JIT。固定长度数组和字符串切片通过标准库方法提供，数组仍是数据闭包。

这些是明确的范围取舍，不是语法分析器先接受、运行时再留空的 TODO。多结果用数据闭包表达，重复计算用 `loop` 表达，参数化装饰器先通过普通调用构造。

## 3. 值、槽与环境

### 3.1 抽象模型

```text
Value   = Int(i64) | Float(f64) | Bool | String | Unit | ClosureRef
Slot    = { value: Value, writable: bool }
Env     = ordered_map<Symbol, SlotRef>
CodeRef = User(CodeId) | Builtin(BuiltinId)
Closure = { identity, env: Env, code: optional<CodeRef>, execution_policy }
Frame   = { current_closure, captured_slots, parameter_slots, local_scopes }
```

这是语义模型；Rust 实际类型与 arena 句柄布局见运行时和内存管理文档。基础值可内联或装箱；字符串不可变；闭包具有稳定身份。`execution_policy` 是运行时元数据，不是可通过字段读写的语言成员。

所有用户 `let` 槽、参数槽和捕获槽默认可写。唯一的预置绑定是只读的 `std` 与 `jit`；`std` 的字段也只读。`self` 是调用上下文中的保留表达式，不是可写槽。

### 3.2 创建、读取与写入

```prim
let a = 1;
let b = a;
let c = &a;
a = 2;
std.assert(b == 1);
std.assert(c == 2);
c = 3;
std.assert(a == 3);
```

- `let a = expr;`：先求值，再创建新槽并绑定 `a`。
- `let c = &place;`：先取得已有槽，再让 `c` 指向同一槽，不创建值槽。
- 读取名字或字段：读槽中当前的值。
- `place = expr;`：先定位并保存目标槽，再求右侧，最后写入；没有返回值。
- 赋值永远写槽，不重新绑定名字。没有 `a = &b`。

`place` 在语义上只能是可写名字或现存闭包字段；括号不改变其性质。字段接收者允许任意表达式，例如 `make().x`，只求值一次。`&(a + b)`、`&self`、`&std` 都无合法的可写槽。

`&` 不是产生指针值的一元运算符。它只允许出现在 `let` 初始化、捕获项和调用实参中；不能被单独返回、相加或放进其他值。需要返回可共享状态时，返回闭包，或返回捕获了该槽的闭包。

### 3.3 值复制与对象共享

基础值按自身内容复制，闭包值复制身份引用。没有隐式深拷贝，也没有复制构造钩子。

```prim
let p = @{ let x = 1; };
let q = p;
let alias = &p;
q.x = 7;
std.assert(p.x == 7);
p = @{ let x = 9; };
std.assert(q.x == 7);
std.assert(alias.x == 9);
std.assert(p != q);
```

`p` 与 `q` 起初是两个槽，保存同一个闭包；`alias` 与 `p` 是同一个槽。重写 `p` 的槽不会改写 `q`。若需要独立对象，应再次调用构造闭包，明确创建需要独立的状态。

## 4. 作用域与块

`{ ... }` 始终是立即执行的词法块；空块合法并返回 `()`。没有字典与块之间的猜测。

```prim
let x = 10;
let y = {
    let x = x + 1;
    x * 2
};
std.assert(x == 10);
std.assert(y == 22);
std.assert({ 1; } == ());
```

块顺序执行语句，最后一个不带分号的表达式是尾值；没有尾表达式就返回 `()`。分号是语句终止符，没有自动补分号，也不接受独立空语句 `;`。

- 普通块、`if` 分支、`loop` 循环体可以访问外层词法绑定。
- 同一作用域不能重复声明；内层可以遮蔽外层。
- 声明的名字从初始化完成后可见。`let x = x + 1;` 的右侧查找外层 `x`，不存在就报名字解析错误。
- 不提升声明，不允许读取稍后声明的变量。
- `std`、`jit` 不允许被声明、参数或捕获项遮蔽。
- 顶层也可以有尾表达式；其值是脚本结果，CLI 默认不自动打印。正常完成退出码为 0，语言错误非零；整数尾值不充当进程退出码。

只在创建可调用闭包时建立显式捕获边界。嵌套一个普通块不要求重写捕获列表。

## 5. 可调用闭包

### 5.1 唯一的构造形式

```prim
let add = $[](x, y) { x + y };
std.assert(add(2, 3) == 5);
```

形式为 `$[captures](parameters) { body }`。`[]` 即使为空也不可省略。闭包表达式是延迟执行的 closuring：求值时只建立捕获环境并保存代码，函数体此时不执行；每次调用才执行一次 closuring。命名只用 `let`；不再有单独的命名函数语法。

每次求值闭包字面量都产生新身份；即使代码和捕获相同，也不是同一个闭包。每次调用创建新的参数槽与局部槽，捕获环境属于闭包并在调用之间保留。

### 5.2 显式捕获

```prim
let x = 10;
let snapshot = $[x]() { x };
let shared = $[&x]() { x };
x = 20;
std.assert(snapshot() == 10);
std.assert(shared() == 20);
```

- `[x]`：在闭包构造时读取外层 `x`，创建闭包私有槽并复制该值。
- `[&x]`：在闭包构造时取得外层可写槽，闭包与外层共享它。
- 捕获项只允许名字，不允许表达式、字段路径或重命名。需要这些功能时先 `let` 一个局部名字。
- 列表按源码从左到右处理；同名重复捕获是错误。
- 函数体可见捕获、参数、局部变量、`self`、`std`、`jit`，不能继续向定义位置的其他外层名字查找。
- 捕获名与参数名不得重复；函数最外层局部声明也不能重复这些名字。嵌套普通块可以遮蔽它们。

值捕获不是“每次调用复制”或“只读捕获”：

```prim
let n = 0;
let next = $[n]() {
    n = n + 1;
    n
};
std.assert(next() == 1);
std.assert(next() == 2);
std.assert(n == 0);
```

捕获一个闭包值时，仍按同一套复制规则共享对象身份；`[obj]` 只快照外层槽中的闭包引用，不深拷贝 `obj`。

嵌套闭包在构造时从当前可见作用域取捕获。若最内层需要更外层名字，中间闭包也必须显式取得该名字，不能跨越捕获边界。

### 5.3 调用与参数

```prim
let increment = $[](&target, delta) {
    target = target + delta;
};
let n = 4;
increment(&n, 3);
std.assert(n == 7);
```

普通参数 `x` 对应普通实参 `expr`：求值后复制到新槽。引用参数 `&x` 对应引用实参 `&place`：共享已有可写槽。调用处必须精确匹配模式，不隐式取引用或解引用。

```text
f(x) 配普通参数：合法。
f(&x) 配引用参数：合法。
f(x) 配引用参数，或 f(&x) 配普通参数：ArgumentModeError。
```

完整求值顺序：先求 callee，检查可调用性、参数数量和实参模式；成功后从左到右求值实参/定位引用实参；全部完成后才进入函数体。数量或模式错误不执行实参副作用。较晚实参求值失败时，已经完成的实参副作用不回滚。

callee 和已经求得的实参在后续求值期间保持存活。字段调用 `obj.f(a)` 只是先读 `obj.f` 再调用，没有隐式接收者参数，也没有方法绑定。

### 5.4 `self` 与递归

```prim
let factorial = $[](n) {
    if n < 0 { return 0; };
    if n == 0 { 1 } else { n * self(n - 1) }
};
std.assert(factorial(5) == 120);
```

`self` 表示当前正在执行的可调用闭包，包括它当前的环境与执行策略。只能出现在可调用闭包的函数体及其中普通块/数据闭包初始化体内；嵌套可调用闭包里的 `self` 指向内层闭包。

`self` 不能被绑定或赋值，也不自动成为环境字段。这样递归不依赖正在初始化的外层变量，不要求为每个递归函数创建自引用槽。需要将外层 `self` 交给内层闭包时，先 `let outer = self;` 再显式捕获 `outer`。

Core 1 不提供互递归声明组；可用预先构造的数据闭包及槽共享表达，但不是必需语法。

## 6. 数据闭包与字段

`@{ ... }` 是立即执行的 closuring：立即执行初始化体，将该体最外层直接声明的绑定作为环境返回。它的 `code` 为空，不能调用。

```prim
let Point = $[](x, y) {
    @{ let x = x; let y = y; }
};
let p = Point(3, 4);
std.assert(p.x == 3);
p.y = 8;
```

初始化体的规则：

1. 可以访问外层词法绑定；它是立即执行的，不创建隐式延迟捕获。
2. 只能包含带分号的语句，不允许尾表达式；返回值固定是新数据闭包。
3. 只有直接在初始化体中执行的 `let` 绑定成为字段。读取外部名字不会导出该名字；嵌套块声明也不导出。
4. `let field = &place;` 导出共享槽；普通 `let` 导出新槽。导出时不再复制一遍。
5. 字段集合构造完成后固定；允许改写现有可写字段，不允许添加、删除字段。缺失字段报 `MissingField`。
6. 初始化体是控制转移边界：不能从里面 `return` 到外部函数，也不能 `break`/`continue` 到外部循环。其内部新建的循环可以正常跳转，内部新建的可调用闭包可以正常返回。
7. 初始化失败不发布结果；已经发生的外部副作用不回滚。

`@{}` 是合法空数据闭包，`{}` 是返回 `()` 的空块。

可调用闭包的环境也通过同样的字段操作可见：字段恰好是显式捕获项，参数、调用局部变量、`self`、代码地址都不是字段。

```prim
let n = 0;
let next = $[n]() { n = n + 1; n };
next.n = 10;
std.assert(next() == 11);
```

Core 1 不设私有字段。公开捕获环境是闭包统一模型的一部分，不是调试后门。

### 6.1 有状态对象与取出的方法

```prim
let Counter = $[](initial) {
    @{
        let value = initial;
        let next = $[&value]() {
            value = value + 1;
            value
        };
        let get = $[&value]() { value };
    }
};
let counter = Counter(0);
let next = counter.next;
std.assert(next() == 1);
std.assert(counter.get() == 1);
counter.value = 40;
std.assert(next() == 41);
```

这里没有类、方法表或隐式 `this`。`next` 与 `get` 通过捕获共享 `value` 槽；把 `next` 取出来仍保有该槽。多返回值同样用 `@{ let quotient = ...; let remainder = ...; }` 表达。

## 7. 控制流与结果

### 7.1 条件

```prim
let sign = $[](n) {
    if n > 0 { 1 } else if n < 0 { -1 } else { 0 }
};
std.assert(sign(-5) == -1);
```

条件必须是 `bool`，不接受数字、字符串或闭包的隐式真值。只执行被选中的分支。没有 `else` 且条件为假时返回 `()`；为真时返回 then 块的值。

### 7.2 循环

```prim
let i = 0;
let total = 0;
let result = loop {
    if i == 5 { break total; };
    i = i + 1;
    if i == 3 { continue; };
    total = total + i;
};
std.assert(result == 12);
```

`loop` 无条件重复其块，每轮新建循环体的局部作用域。普通尾值被丢弃并进入下一轮；`break expr;` 结束最近循环并成为循环结果；`break;` 结果为 `()`；`continue;` 进入下一轮。无标签，不跨越可调用闭包或数据闭包初始化边界。

`return expr;` 从当前可调用闭包返回，`return;` 返回 `()`。普通块不建立返回边界。顶层 `return`、循环外 `break`/`continue` 都是静态语义错误，包括不可达代码中的这些错误。

内部解释器可以用以下控制结果，但它们不是语言值：

```text
Completion = Normal(Value) | Return(Value) | Break(Value) | Continue | Error
```

运行时错误终止当前脚本，Core 1 无 `try`/`catch`。已经完成的写入和输出保留，不做事务回滚。

## 8. 基础类型与运算

动态类型表示槽可保存不同种类的值；没有隐式转换。类型名是 `std.type(value)` 返回的字符串，不是声明语法。

| 类型 | 语义 |
| --- | --- |
| `int` | 有符号 64 位；溢出报 `IntegerOverflow` |
| `float` | IEEE 754 binary64、round-to-nearest ties-to-even；Core 1 只接受有限值 |
| `bool` | `true` / `false`，不是整数 |
| `str` | 不可变、有效 UTF-8 字符串，允许转义得到的 NUL |
| `unit` | 唯一值 `()`；没有 `null` / `none` 别名 |
| `closure` | 按身份相等；可有或没有代码入口 |

| 运算 | 合法输入与结果 |
| --- | --- |
| 一元 `+`、`-` | `int` 或 `float`，保留种类；负整数最小值取负溢出 |
| `+ - * /` | 两个同种数字；`str + str` 另表示连接 |
| `%` | 两个 `int`；商向零截断，余数与被除数同号或为零 |
| `< <= > >=` | 两个同种数字，返回 `bool` |
| `== !=` | 任意值；不同种类不相等，同种按下述规则 |
| `!` | 一个 `bool` |
| `&&`、`||` | 左侧必须 `bool`；按需求右侧并要求 `bool`；结果也是 `bool` |

整数 `/` 向零截断；`-7 / 3 == -2`，`-7 % 3 == -1`。整数除/模零报 `DivisionByZero`；`INT64_MIN / -1` 和 `INT64_MIN % -1` 都报 `IntegerOverflow`，便于两个执行后端保持一致。

浮点除以正/负零也报 `DivisionByZero`。浮点运算若产生非有限值报 `FloatRangeError`；下溢允许舍入到次正规数或零。禁止 fast-math 和浮点乘加收缩改变逐运算舍入规则。字面量溢出属于静态字面量错误。浮点正负零相等。

同种相等规则：数字按数值，字符串按 UTF-8 字节序列，布尔按值，两个 unit 总相等，闭包按身份。字符串不做 Unicode 规范化。闭包不做字段递归比较；循环图也不影响相等判断。

求值顺序除短路外均为从左到右。比较运算同属一层且不连写；`a < b < c`、`a == b == c` 均是语法错误，需要写成两次比较和 `&&`。

## 9. 装饰器与手动 JIT

### 9.1 装饰器是普通闭包变换

```prim
let traced = $[](f) {
    $[f](x) {
        std.print("call");
        f(x)
    }
};
let double = @traced $[](x) { x * 2 };
std.assert(double(3) == 6);
```

`@name` 只能修饰紧随其后的可调用闭包字面量或另一层装饰器；`@{...}` 则始终是数据闭包。装饰器名字为单个标识符；复杂表达式先绑定名字。

```text
@a @b $[](x) { x }
等价于：a(b($[](x) { x }))
```

遵循普通调用的求值顺序：先读并验证 `a` 的可调用性和单个值参数模式，再处理 `b`，再构造原始闭包，最后由内到外应用。每层装饰器返回值必须是可调用闭包，否则报 `DecoratorResultError`。这个结果检查是装饰器语法额外施加的约束；普通调用 `a(b(...))` 本身没有这个约束。

装饰器在表达式求值时执行一次，没有编译期宏求值。`@decorator(args)` 不是语法；使用 `let configured = decorator(args);` 再 `@configured`。

### 9.2 `@jit` 的精确定义

```prim
let sum_to = @jit $[](n) {
    let i = 0;
    let total = 0;
    loop {
        if i > n { break total; };
        total = total + i;
        i = i + 1;
    }
};
std.assert(sum_to(100) == 5050);
```

`jit` 是内置只读可调用闭包，`@jit literal` 与 `jit(literal)` 具有相同效果。它接受一个 Prim 用户可调用闭包，返回一个**共享原捕获槽**、使用相同源代码但带 `JitRequired` 执行策略的新闭包。原闭包保持原策略，新闭包身份不同。对已经是 `JitRequired` 的闭包再次 `jit` 返回自身。

- 装饰时仅标记，首次实际调用时编译；没有用于触发编译的调用计数、热度阈值或自动触发。
- 首次调用先完成正常的 callee/实参验证与求值，再编译并执行函数体。编译失败时，实参求值的副作用已发生，函数体没有执行。
- 编译以 `CodeId` 为单位，不按实参类型特化；Core 1 保留动态类型，未知运算调用统一运行时。
- 同一代码的不同闭包可共享机器码，但各自传入真实环境，绝不固化捕获值或地址。
- `self` 指向实际调用的 JIT 闭包，递归通过统一分发器再次进入该策略。
- JIT 函数调用未装饰函数时，后者仍解释执行；调用已装饰函数时进入其本机路径。
- 对数据闭包、基础值或内置宿主闭包使用 `jit` 报 `JitTargetError`。
- IR 生成、验证或 ORC 编译失败是明确的 `JitCompileError`；无静默解释回退。
- 已执行的本机函数发生语言错误时直接传播，不能重新解释执行函数体，否则副作用会重复。

普通装饰器生成的新包装闭包没有自动继承被包装闭包的 JIT 策略。`@jit @traced ...` 编译外层包装；`@traced @jit ...` 解释包装、在它调用内部闭包时进入 JIT。二者都遵循普通函数组合。

具体编译、缓存、ABI 与 GC 根协议见 [jit-runtime.md](jit-runtime.md)；槽语义为何适合本机编译见其 §3.1。手动 JIT 已由 Rust / LLVM ORC 实现。

## 10. 标准环境与交互

完整的 **168 个内置接口**以 [prim-builtin.md](prim-builtin.md) 和 `prim --builtins` 为准。标准环境是只读数据闭包，内置函数具有固定参数数量，所有参数按值传递。

| 分组 | 能力 |
| --- | --- |
| std 顶层 | 输出、行输入、类型/转换/断言、固定长度数组、动态字段读写 |
| std.time | 单调时钟、Unix 时间、可中断 sleep |
| std.random | 设置种子、整数区间与浮点随机数 |
| std.text | Unicode 标量索引/切片、重复、修剪、查找和替换 |
| std.math | 数值范围、取整、幂、平方根和三角函数 |
| std.env / std.fs | 脚本参数、环境变量、当前目录、文本文件读写 |
| std.term | TTY、备用屏幕、原始按键、光标/颜色、窗口大小及恢复 |
| std.gc | 主动收集和内存统计 |
| jit | 独立预置装饰器 |

`std.array(n, initial)` 构造字段为 `"0".."n-1"` 的固定数据闭包；`std.get/set/has` 提供动态字段访问。不添加数组字面量或 `[]` 索引语法，闭包身份、值复制和 GC 规则保持一致。`std.len` 对字符串计算 Unicode 标量数，对闭包计算字段数。

`std.str` 使用运行时统一显示规则；浮点采用 Rust `f64::to_string`，没有小数点或指数时补 `.0`，负零显示 `-0.0`。这保证往返显示，不承诺总字符数最短的科学记数法选择。

`std.int/float` 只接受数字；交互文本使用 `std.parse_int/parse_float`，无法解析时返回 `()`。行输入、按键超时、EOF 的返回值含义在内置参考中逐项定义。

终端模式在正常结束、语言错误以及可处理的 SIGINT/SIGTERM 中断后恢复。CLI 不累计历史终端帧到内存。脚本参数通过 `prim file.pr -- args...` 传入，源码后缀固定为 `.pr`。

## 11. 生命周期与内存管理

实现使用单线程标记清扫的 Slot/Closure arena。对象通过整数句柄连接，不使用 Rust 引用作为语言引用；存活期间句柄稳定，底层 Vec 可以扩容/收缩，物理元素地址不承诺稳定。

字符串由 `Rc<String>` 管理；闭包与槽之间的循环由 GC 追踪。参数槽、局部槽和值捕获槽创建在受管 arena 中，槽捕获和引用参数复用已有句柄，因此逃逸后不会指向失效栈地址。

根包括预置环境、活动 Frame 当前 PC 的活跃寄存器、当前闭包、返回值和最后脚本结果。编译器计算控制流活跃性；GC 清空死寄存器，避免已经离开块的对象/字符串保留到函数结束。

自动 GC 在运行时操作完成且结果已发布后，按分配阈值触发；也可用 `std.gc.collect()` 主动收集。返回值先保护再弹出调用帧，失败路径也清理帧。arena 清扫后复用空闲索引、截去尾部空洞，并在容量显著过大时收缩。

LLJIT 管理本机代码直到 Runtime 销毁；失败模块通过 ResourceTracker 及时移除。GC 不运行用户析构器。完整所有权、根映射、审计发现、Valgrind 结果与复现命令见 [memory-management.md](memory-management.md)。

## 12. 完整的组合示例

```prim
let Counter = $[](initial) {
    @{
        let value = initial;
        let next = @jit $[&value](step) {
            value = value + step;
            value
        };
        let read = $[&value]() { value };
    }
};
let a = Counter(0);
let b = Counter(100);
let next = a.next;
std.assert(next(2) == 2);
std.assert(a.read() == 2);
std.assert(b.next(3) == 103);
std.assert(a.next.value == 2);
std.assert(b.read() == 103);
```

这个例子同时验证：数据闭包、显式槽捕获、方法取出、解释/本机互调、代码共享而环境独立。实现与答辩都应以这种语义可观察的例子为主。

## 13. 验收边界与迁移

规范中的合法示例必须先通过前端，再由解释执行与手动 JIT 路径产生一致结果。非法示例必须区分词法、语法、名字解析、静态语义、运行时与 JIT 基础设施错误。

| 旧写法或设想 | Core 1 |
| --- | --- |
| `$name(args) { ... }` | `let name = $[](args) { ... };` |
| `let x;` 隐式导入 | 可调用闭包显式写 `[x]` 或 `[&x]` |
| `@struct`、构造函数特殊体 | 普通闭包尾值返回 `@{ ... }` |
| `@{ ...; tail }` | 初始化体只含语句，字段通过 `let` 声明 |
| `{}` 是字典 | `{}` 是块，`@{}` 是数据闭包 |
| 默认深拷贝闭包 | 复制闭包身份引用；独立状态显式重新构造 |
| `null`、多种数值宽度、类型联合 | `()`、`int`、`float`，无注解 |
| 自动热点、类型推测 JIT | 显式 `@jit`，首次调用编译通用代码 |

阅读顺序：本文 → [词法规则](lexical-spec.md) → [Lexer](lexer-design.md) → [Parser](parser-design.md) → [JIT](jit-runtime.md)。[语法速查](syntax-guide.md)仅提供导航与常见写法。

## 14. 交互会话边界

脚本文件遵循上述词法作用域规则。REPL/重复 -e 将每条输入作为新的顶层作用域，导入现存全局绑定，允许新输入 let 遮蔽旧名字；旧闭包仍指向原捕获槽。同一条输入内重复 let 仍报错。输入只执行一次，完成或报错后导出已经执行的声明，未执行的声明不加入环境。详见 [cli.md](cli.md)。
