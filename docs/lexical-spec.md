# Prim Core 1 词法规则

版本：2026-10-19。本文是源码到 Token 的规范；扫描器接口与错误策略见 [lexer-design.md](lexer-design.md)，文法见 [parser-design.md](parser-design.md)。本文对应当前 Rust 手写扫描器；输入接口、Token 实际结构与遇错即停行为见 Lexer 文档。

## 1. 源码与位置

- Prim 源文件统一使用 `.pr` 扩展名，例如 `hello.pr`；命令行可执行文件名为 `prim`。
- 输入是有效 UTF-8，不接受文件开头的 BOM；源码中的原始 NUL 字节非法，包括字符串和注释内。字符串转义 `\0` 可以产生值中的 NUL。
- 标识符只用 ASCII；字符串与注释允许 Unicode。
- 空白只有空格、Tab、LF、CRLF、单独 CR。CRLF 计一次换行。
- 换行没有语法含义，不生成换行 Token，不自动插入分号。
- Span 使用原文件的零基字节偏移、半开区间 `[begin, end)`；显示行列从 1 开始。Span 只保存字节偏移，行列在诊断渲染时计算，Tab 按 4 列停止位展开。
- 空文件合法；EOF 的 Span 为 `[文件字节数, 文件字节数)`。

Lexer 不匹配括号，不判断一元/二元运算符，也不识别装饰器语义。它只输出 `-`、`@`、`$` 等各自的 Token。

## 2. 标识符与关键字

下文大写 Token 名是文法记号：实际实现将关键字表示为 `Word("let")` 等，将标点表示为 `Sym("+")` 等；所有进制整数统一为 `Int(raw)`，浮点为 `Float(raw)`，字符串为已解码的 `Str(value)`，EOF 为 `Eof`。没有 ERROR Token。

```text
IDENT = [A-Za-z_][A-Za-z0-9_]*
```

区分大小写。先扫描完整标识符，再对完整词素做关键字查表；`letter` 不能拆成 `let` 和 `ter`。`_` 是普通名字，不是丢弃模式。

| 词素 | Token |
| --- | --- |
| `let` | `KW_LET` |
| `if` | `KW_IF` |
| `else` | `KW_ELSE` |
| `loop` | `KW_LOOP` |
| `break` | `KW_BREAK` |
| `continue` | `KW_CONTINUE` |
| `return` | `KW_RETURN` |
| `true` | `KW_TRUE` |
| `false` | `KW_FALSE` |
| `self` | `KW_SELF` |

`std`、`jit`、`int`、`float`、`str`、`bool`、`unit`、`null`、`del` 都是 `IDENT`。其中 `std`、`jit` 由语义阶段作为只读预置名字提供；类型名字不因此获得类型注解语法；未绑定的 `null`/`del` 作为普通名字报未定义。

## 3. 数字

### 3.1 整数

使用下划线分组，只允许在同一基数的两位数字之间出现单个 `_`。单引号不再用作数字分隔符。

```text
D       = [0-9]
H       = [0-9a-fA-F]
O       = [0-7]
B       = [01]
DEC     = D ("_"? D)*
HEX     = H ("_"? H)*
OCT     = O ("_"? O)*
BIN     = B ("_"? B)*
INT_DEC = DEC
INT_HEX = "0" [xX] HEX
INT_OCT = "0" [oO] OCT
INT_BIN = "0" [bB] BIN
```

合法：`0`、`007`、`1_000`、`0xFF`、`0o755`、`0b10_10`。前导零不改变十进制解释。

非法：`1__0`、`10_`、`0x`、`0x_FF`、`0o8`、`0b102`、`42i64`。`_10` 是合法标识符，不是数字。

负号不属于字面量，`-42` 输出 `MINUS INT_DEC`。整数宽度与范围检查在语义阶段进行，避免 Lexer 无法表示最小负数。

### 3.2 浮点数

```text
EXP       = [eE] [+-]? DEC
FLOAT_DEC = DEC "." DEC EXP? | DEC EXP
```

合法：`0.5`、`1.0`、`1e3`、`2.5e-3`、`1_000.25`、`1e1_0`。

不支持 `.5`、`1.`、十六进制浮点、数字类型后缀、`nan`/`inf` 字面量。小数点两侧必须有数字；指数可有正负号。

点号只在“数字扫描状态且后面紧跟十进制数字”时并入小数部分。因此：

| 源码 | Token 或错误 |
| --- | --- |
| `1.0` | `FLOAT_DEC` |
| `1.x` | `INT_DEC DOT IDENT`；运行时字段接收者类型错误 |
| `1.` | `INT_DEC DOT`；Parser 报缺少字段名字 |
| `.5` | `DOT INT_DEC`；Parser 报表达式不能以点开头 |
| `1.2.3` | `FLOAT_DEC DOT INT_DEC`；Parser 报字段名应为标识符 |
| `1e+` | `Err(InvalidNumber)` |
| `0x1e+2` | `INT_HEX PLUS INT_DEC`；十六进制的 `e` 不是指数 |

### 3.3 错误数字不能伪装成多个合法 Token

从数字开始后，连续 ASCII 字母、数字、下划线必须纳入候选检查。`123abc`、`1e2x`、`0b102` 都整体报 `InvalidNumber`，不能分别切成合法前缀与后续名字/数字。

候选扫描按基数分状态：只有十进制指数位置允许吸收一个 `+`/`-`；只有十进制小数位置按上一节条件吸收 `.`。遇到其他标点或空白终止候选。错误 Span 覆盖整个候选；当前 Error 只有一个主 Span，不另保存第一处坏字符的附加 Span。

`1_foo` 是错误数字；`1 + foo` 是三个正常 Token。`1'000` 切成整数、非法单引号、整数，并在词法阶段使整个文件失败；不兼容旧分隔符。

## 4. 字符串

仅支持双引号字符串，值必须是有效 UTF-8。不支持单引号、原始字符串、多行字符串、插值或相邻字符串自动连接。

允许普通 Unicode 字符，但不允许未转义的 U+0000–U+001F、U+007F；实际换行在闭引号前出现时是未闭合字符串错误。

| 转义源码 | 解码结果 |
| --- | --- |
| `\"` | 双引号 |
| `\\` | 反斜杠 |
| `\n` | LF |
| `\r` | CR |
| `\t` | Tab |
| `\0` | NUL |
| `\u{H...}` | 1–6 位十六进制表示的 Unicode 标量值 |

`\u{...}` 必须在 `0..10FFFF` 内且不在代理项区间 `D800..DFFF`。不支持 `\xHH`，避免制造无效 UTF-8；也不接受 `\'`，双引号内的单引号直接写即可。

```prim
let greeting = "你好，Prim";
let newline = "line1\nline2";
let symbol = "\u{1F600}";
let nul = "\0";
std.assert(std.len(nul) == 1);
```

Lexer 同时验证并解码字符串，Token 保存解码后的 String 与原源码 Span；错误位置指向原源码。数字范围检查另在 Core IR 编译阶段进行。

## 5. 运算符与标点

先识别注释，再按最长匹配识别多字符运算符。

| 词素 | Token |
| --- | --- |
| `==` / `!=` | `EQEQ` / `NEQ` |
| `<=` / `>=` | `LE` / `GE` |
| `&&` / `\|\|` | `ANDAND` / `OROR` |
| `=` | `EQ` |
| `+` / `-` / `*` / `/` / `%` | `PLUS` / `MINUS` / `STAR` / `SLASH` / `PERCENT` |
| `<` / `>` / `!` | `LT` / `GT` / `BANG` |
| `&` | `AMP` |
| `(` / `)` | `LPAREN` / `RPAREN` |
| `[` / `]` | `LBRACK` / `RBRACK` |
| `{` / `}` | `LBRACE` / `RBRACE` |
| `.` / `,` / `;` | `DOT` / `COMMA` / `SEMI` |
| `@` / `$` | `AT` / `DOLLAR` |

没有 `+=`、`++`、`->`、`:`、单个 `|`、反引号标签。由现有 Token 拼出的不支持组合由 Parser 拒绝，例如 `+=` 输出 `PLUS EQ`；根本无 Token 的字符由 Lexer 报错。

`@jit` 必须输出 `AT IDENT("jit")`，不能生成专门的 JIT Token。`@{}` 输出 `AT LBRACE RBRACE`。`$[]()` 中所有符号独立输出，空白不影响其组合。

## 6. 注释

```text
// 到 LF、CRLF、CR 或 EOF
/* 到第一个 */
```

块注释不嵌套，内部 `/*` 只是普通文本。注释按空白处理，不连接两侧词素：`ab/*...*/cd` 是两个标识符，不能变为 `abcd`。

字符串内的注释符号没有注释意义，注释内的引号与括号也没有字符串或括号意义。未闭合块注释返回覆盖起点到 EOF 的错误，扫描停止。

## 7. 错误归属

| 阶段 | 负责的问题 |
| --- | --- |
| 文件读取/Lexer | 文件读取拒绝无效 UTF-8；Lexer 拒绝开头 BOM、原始 NUL、非法字符/数字/转义和未闭合字符串/注释 |
| Parser | 括号不匹配、缺分号、非法表达式结构、`@jit` 后缺少闭包字面量 |
| Resolver/静态语义 | 未定义名字、捕获遗漏、重复绑定、非法赋值目标、跨边界控制转移、字面量数值超范围 |
| Runtime | 动态类型、缺失字段、参数模式/数量、算术错误、调用不可调用值 |
| JIT 基础设施 | LLVM IR 解析/验证、ORC 模块加入或入口查询失败；没有外部编译器子进程和临时共享库 |

任何前端错误都阻止该文件执行；当前实现报告首个错误即停止，没有错误恢复后的 AST。
