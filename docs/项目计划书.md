# Prim 语言设计与实现项目计划书

**课设主题**：用闭包统一函数、对象和状态，并支持手动 LLVM JIT。

**实施版本**：Rust Core 1 与交互标准库，Linux x86_64 / LLVM 14。

**文档定位**：按最终采用的实现路线整理目标、交付内容、验证与后续工作。代码位于 `src/prim-rs`，源码后缀 `.pr`，可执行文件名 `prim`。

## 一、项目目标

用较少的语言机制实现从源码到本机执行的完整链路，并能编写交互终端程序。核心命题是一切皆闭包：closure 是静态的数据，closuring 是动态构造数据的过程；对象是立即执行的 closuring，函数是延迟执行的 closuring。

目标包括：

1. 明确定义值、名字、槽、捕获与调用的关系。
2. 实现可运行的词法/语法前端、名字解析、Core IR 和解释器。
3. 通过 `@jit` 手动选择函数，首次调用编译为当前进程可调用的机器码。
4. 在两种执行方式之间保持状态共享、求值顺序与错误语义一致。
5. 支持闭包逃逸、循环对象回收及长期交互的资源清理。
6. 提供完整内置 API，并用终端贪吃蛇验证真实按键与屏幕交互。

## 二、最终技术选择

| 部分 | 当前实现 |
| --- | --- |
| 主语言与构建 | Rust 2024 edition，Cargo workspace；Rust 1.91+ |
| Lexer | 手写 UTF-8/ASCII 状态机，遇到首个错误停止 |
| Parser | 手写递归下降与 Pratt 表达式解析 |
| 静态检查 | ir::Builder 集成名字解析、捕获检查、place 和控制目标检查 |
| Core IR | 寄存器指令、跳转/分支/返回与逐指令 Span |
| 解释执行 | 直接解释 Core IR |
| 语言对象 | Value、Slot arena、Closure arena；索引句柄连接 |
| 内存管理 | CFG 活跃根、标记清扫、Rc 字符串、arena 尾部回收 |
| JIT | 动态链接 libLLVM，经 C API 使用 ORC LLJIT |
| 本机优化 | 原生控制流、带溢出检查的整数加减乘；其他动态操作共用 helper |
| 终端 | Linux termios/poll/ioctl、ANSI 屏幕、可中断等待与恢复 |
| 测试 | Cargo 单元/集成测试、解释/JIT 差分、真实 PTY 与 Valgrind |

项目没有第三方 Rust crate，不构建 LLVM 源码、不静态链接 LLVM，不使用外部 Clang 子进程或临时共享库作为 JIT 路线。旧 C++/re2c/Bison 材料位于 `src.bak/`，不是当前构建入口。

## 三、语言与标准库范围

### 3.1 语言

基础值为 int、float、bool、str、unit、closure。支持 let/赋值/别名、词法块、显式捕获、值/引用参数、数据闭包、字段访问、装饰器、self 递归、条件、短路、loop/break/continue/return。

同一套字段槽模型表达对象状态和函数环境；复制闭包值保留身份，`&` 显式共享槽。没有隐式深拷贝、隐式捕获、类、继承、运算符重载或类型注解。

### 3.2 标准库

完整 168 个接口见 [prim-builtin.md](prim-builtin.md)。覆盖文本/行输入/整段 stdin、stdout/stderr、固定数组与序列、动态字段访问、时间与 UTC 日历、随机数、数学、位运算、脚本参数、文件与目录、进程、终端绘图/按键/颜色、AST 解析、运行时检查及 GC 统计。

数组使用数据闭包的数字字段，不添加列表字面量或方括号索引语法。多结果同样返回数据闭包，例如终端大小 `{width,height}`。

### 3.3 贪吃蛇交付

`src/prim-rs/examples/snake.pr` 是真实可玩的终端程序。支持方向键/WASD、暂停、重开、退出、缩放提示、增长、分数、撞墙/自撞和胜利状态。蛇身用环形队列，地图用固定数组，移动函数显式 `@jit`。

游戏提供 `-- --self-test` 模式，可在无 TTY 的 CPU worker 上重复验证逻辑；输入和恢复另外使用 PTY 验证，二者不互相替代。

## 四、执行架构

```text
.pr 源码
  → syntax.rs：Token / AST
  → ir.rs：名字与控制检查、寄存器指令
  → liveness.rs：逐 PC 活跃寄存器
  → runtime.rs：值、槽、调用与 GC
      ├─ Core IR 解释执行
      └─ @jit：jit.rs → LLVM IR 验证 → ORC 编译 → 本机入口
  → builtins.rs / terminal.rs：标准库与交互
```

JIT 以函数代码节点为缓存单位，闭包实例传入各自环境。机器码不固化捕获值；值类型改变后仍执行动态检查或慢路径。编译失败明确返回错误，本机执行错误不会从头解释重放。

本机回调以 Runtime 指针、Frame 索引和标量参数通信，不暴露 Rust 容器布局。LLVM module/错误消息/ResourceTracker 的所有权在包装层明确处理。

## 五、生命周期与内存审计

根集合包含预置环境、活动帧当前 PC 的活跃寄存器、当前闭包、返回值和最后脚本结果。GC 追踪槽/闭包循环并清空死寄存器；清扫后复用空位，收缩尾部空洞及过大的容量。

审计发现并修复了死寄存器过度保活、大 arena 容量滞留、ORC 失败资源延迟释放及函数元数据重复克隆。交互 CLI 关闭历史输出捕获，终端状态在正常或可处理的异常退出中恢复。

具体复现、修复前后数据和 Valgrind 证据见 [memory-management.md](memory-management.md)。不以 RSS 单独判断泄漏，也不把测试框架的退出残留与 Prim 对象泄漏混为一谈。

### 6.1 解释器 CLI

已实现文件/stdin、重复 -e、多输入持久会话、运行后进入 REPL、check/lex/ast/ir 子命令、JSON/颜色诊断、计时/统计、操作预算、栈深与源码大小限制。REPL 提供加载、变量查看/删除、GC、reset；不会重放历史代码。完整 flags 与退出码见 [cli.md](cli.md)。

## 七、环境与结果边界

所有构建、测试、PTY 与内存审计在动态发现的 GPU=0 CPU pod 上完成。使用共享盘绝对项目路径，中间 Cargo 产物放在 pod `/tmp`，交付二进制与日志位于项目 `build/prim-rs/`。不自行申请 pod，不将重任务回退到开发机。

实测工具链为 Rust 1.95、LLVM 14.0.0、Linux x86_64。build.rs 接受 LLVM 14–18 并切换指针 IR 方言，但尚未验证其他 LLVM 主版本或其他系统。

性能区分解释、首次编译与入口缓存后的执行。局部整数循环已有 O0/O1/O2 对照基准；共享捕获、递归和数组保留通用路径。完整原始样本、编译成本、适用边界见 [优化与测量](optimization.md)，不将一个数值循环的加速推广为所有程序的结论。
